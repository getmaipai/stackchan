## Item 7: NFC and infrared (decided from the hardware, skipped)

- The body has an infrared transmitter and receiver and an NFC module (M5 product README in the tree: "infrared transmitter and receiver ... a full-featured NFC module"). `docs/dev/stackchan-sensor-map.md` lists the NFC chip as an ST25R3916 at I2C address 0x50 from a third-party firmware, and that note says the main unit has no NFC.
- The pinned stock tree has no infrared or NFC code at all (searched `main/`, the stock `xiaozhi-esp32/main` and its docs; the only matches are another vendor's boards). It has no pin number for the infrared parts: the main unit's pin table (`hal/board/config.h`) names none, and the body's other parts sit behind the PY32 IO expander, whose pin map for infrared is not in the tree.
- Driving a guessed pin on a body that also powers two servos is a hardware risk, and an infrared learn and send tool needs a verified transmit pin, receive pin and carrier. NFC needs a full radio driver and an NDEF reader, none of which is in the tree, and has no use in the MaiPai design yet.
- Verdict: no patch. What would unblock it: the body's schematic or a vendor pin list for the infrared transmit and receive lines. Then a small tool behind a Kconfig switch (default n) using the RMT peripheral, allocated only during a call, is about one patch (learn up to 64 pulses, store eight named slots, send).

## Not verified

- Nobody looked at the screen and no camera watched it: that the decorators, face styles, the More pages and the quick settings row look right (three buttons in the last row, a page that fits 240 pixels) is not observed. The code ran without fault; the look is unchecked.
- The decorators and the reaction hook could only draw in the throwaway build, because the unit is muted and both refuse to draw over a mute (the refusal itself was observed on the real build). Word reactions firing from real speech, the quiet sounds, the head dance and the host sending its text to the caption hook (the host may not send the person's words to the unit at all; the unit also reacts to what it says) were not run.
- The More button's touch path and the ten-tap count with a finger: the functions behind them were called, not touched.
- The host half against a live unit: every host test uses a stand-in unit; the settings page was not opened in a browser, only parsed, rendered in six languages and driven through its routes.
- TN07 on a unit: a failing travel save on the setup page and the build stop were checked by tests and by reading, not by making flash unwritable or building with a missing folder on this machine.
- Travel memory with a real key (the brief's last review item): no key exists, so the connected-state number is still the estimate in `travel-2026-11-16.md`.
- The per-person wake phrase is stored and checked only; nothing matches a custom spoken phrase.
- French, German, Portuguese and Italian: screen words are plain ASCII (no accents on the screen, as designed), the Wi-Fi setup page still reads English or Spanish only, the new screens (More, network test, version) read English or Spanish, and the flasher messages read English.
