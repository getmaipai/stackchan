## Boot loop and its cause (first merged image)

Every boot died at `esp_task_stack_is_sane_cache_disabled`. The listening ring task (TB01) keeps its stack in PSRAM and, on its first pass, read the saved choices and the sound policy from NVS (flash). The IMU task, also on a PSRAM stack, reaches the same reader through the pickup reaction. TC02 reads both once on the main task and makes `maipai_tb_prefs` return its cache, with a refresh from the timer task, when the caller's stack is not internal. A test (`test_firmware_trackc_patches.py`) lists every PSRAM-stack task the patches add and fails on an unreviewed one.

A second, older fault shows on cold USB resets only: the camera VSYNC interrupt fires before its queue exists (`xQueueGenericSendFromISR`), the unit reboots once and then boots cleanly. It is in the vendor camera component, not in these patches, and was seen on about half of the USB-reset boots in this session (never on a soft reboot or inside a run).

The first merged image failed int_big (8,704). Fixes, none changing behavior: the "mm" render and the pack boot task no longer hold internal stacks while the wake model loads (render runs on the PSRAM ring task, pack boot starts 15 s after boot), the overlay state, the pack state and the u-law table moved from static internal RAM to PSRAM (3.1 KB), seven long tool descriptions shortened (1.9 KB). The margin on int_big is 384 bytes. A stored look pack now applies 15 s after boot.

Not measured: the pickup (needs the owner to lift the unit).

## Host

`host/maipai_body/unit_prefs.py`: a save sends only the unit keys the person changed, and a reconnect sends only the keys a person ever chose (never a host default). Before this the host sent `speech_bubble false` every time, so the unit's Stock default (bubble on) was lost. The unit still holds the value the old host sent for each of those keys; clearing them needs an NVS erase and was not done.

`remote_activity.py` and `unit_remote.py`: a paired controller's action marks its head, dance, game, find and listen calls `source: remote` and carries the cue token (a long find asks for a fresh cue every 20 s). The photo call goes through the voice link and is not marked yet.

Tests added: `remote_gate_test.c`, `test_firmware_trackc_patches.py`, three prefs and four remote tests. Full host run before the last patches: 4,133 passed, 2 failed (`test_stackchan_touch_core`, `test_stackchan_train4` look core), both in files the faces lane edited at the same time.
