# StackChan bench

Start a local testing console with `stackchan bench`. It binds to `127.0.0.1:9790` and does not need a password. Use `stackchan bench --sim` to exercise the page without a connected unit. Use `--host` and `--port` to select another address; a non-loopback address requires `--token SECRET`, which the page sends as a bearer token for API writes.

With several units, pick one in the Unit list at the top (default: the only unit, or the first online). Every control and the log carry the unit; `GET /api/units` lists them and `?unit=` on `/api/status` and `/api/tools` picks one. A bad unit gets a plain error naming what to do.

The page shows unit status and the raw reported MCP tool list. Lights offers pixel, side and full-ring controls, brightness, off and animation controls. Meaning colors are reference only and are not applied remotely. Face offers the built-in face names, caption, look direction and night and clock controls. Head and body offers bounded pan and tilt, home, dance, nod and touch simulation. Sound offers earcons, volume and typed speech. Privacy controls change mute, camera and quiet cues; the page never opens the camera or microphone. The generic tool caller exposes the unit's reported schema and raw reply, with dangerous tools hidden until enabled and requiring the word `CONFIRM`. The log keeps the latest 200 calls and can be copied, saved as JSON, or replayed.

## Checks owed by the bench (not the owner)

- **Quiet now and the quiet schedule (decision 22, firmware SF52).** On a unit with SF52: set Quiet now on the settings page, then `self.audio.sound_info` must answer `quiet_now` true and `night` true, event sounds stay silent, an alarm you set still rings, and the shutter click still plays. Turn it off and sounds return. Then save a schedule for Monday to Friday 22:00 to 07:00: quiet at 23:00 on a Thursday and at 03:00 on a Saturday, not at 23:00 on a Saturday. Record the result in `docs/dev/bench-evidence/`.

- **Robot network capture (owed by the bench, not the owner).** Proves the robot contacts only your host. Needs a Mac on Wi-Fi with Internet Sharing, one robot and its host.
  1. On the Mac: System Settings, General, Sharing, Internet Sharing: share the Mac's connection to Wi-Fi with a name and password of your choice (a throwaway network). The shared network is the `bridge100` interface.
  2. Join the robot to that network (setup page on the robot), pair it with the host as usual, and set the host's address in the robot's setup to the Mac's address on `bridge100`.
  3. Start a capture: `sudo tcpdump -i bridge100 -n -w robot-capture.pcap` (leave it running).
  4. Use the robot for at least five minutes: wake word and a spoken turn, a timer, a game, the lock, a photo from the settings page, and then leave it idle for two minutes. Reboot the robot once during the capture so its start-up traffic is included.
  5. Stop the capture (Control-C) and list every destination other than the host: `tcpdump -n -r robot-capture.pcap | awk '{print $5}' | sort -u`, or `bash scripts/stackchan-egress-proof.sh robot-capture.pcap <host address>`, which fails if any destination other than the host appears.
  6. Record the result (date, firmware build, duration, destination list, pass or fail) in `docs/dev/bench-evidence/`, and replace the "No capture has been taken yet" line of the egress table with it. Keep the pcap itself out of the repository: it holds the robot's Wi-Fi traffic.

- **Host update swap on the Studio service (owed by the bench, not the owner).** `stackchan service update` is tested with fakes only. On the Mac Studio with the host installed as a service (`stackchan service install`): (1) run `stackchan service update --from <a folder with the current host source>` and confirm `stackchan service status` says running and `stackchan status` says everything runs on the new version folder under `host-versions/`; (2) run it again with a deliberately broken source (a copy whose `maipai_body/__init__.py` raises) and confirm the old version is back, `stackchan service status` prints "Last update: The update did not take", and the robot reconnects; (3) repeat on a Linux machine with systemd when one is available. Record the date, the commands and the result in `docs/dev/bench-evidence/`.

- **Service handover button on the Studio (owed by the bench).** The handover rule is tested with fakes only (`host/tests/test_service_handover.py`). With the host started by hand (`stackchan run`) and no service installed: open `/health` on the host computer, press **Keep the host running**; the page stops, `stackchan service status` says running within a minute, the robot reconnects, and `host-versions` is unchanged. Then make it fail: with a copy whose startup raises, confirm the host comes back the old way and `service-handover.json` holds the message. Record the date and result in `docs/dev/bench-evidence/`.
